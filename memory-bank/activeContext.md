### 关键架构决策

#### 1. 反向 RPC 设计
- **emit 模式**：单向通知，不等待响应（用于状态更新）
- **call 模式**：请求-响应，可设置超时和默认值（用于玩家输入）
- **reserve 模式**：收集请求描述符，用于批量执行

#### 2. 状态管理策略
- 使用 Vue 3 Composition API 的 `ref` 和 `computed`
- 通过 `provide/inject` 在组件树中共享游戏状态
- `GameService` 类封装所有 RPC 方法调用

#### 3. 房间生命周期
1. **创建房间**：HTTP API `/api/rooms` (POST)
2. **加入房间**：HTTP API `/api/rooms/:id/join` (POST)
3. **准备游戏**：HTTP API `/api/rooms/:id/ready` (POST)
4. **开始游戏**：当所有玩家准备就绪时自动触发 `onAllReadyStart` 回调
5. **游戏进行**：服务器通过 RPC 驱动游戏流程
6. **断开处理**：自动清理房间中的玩家座位

#### 4. 卡牌传输机制
- 所有卡牌类必须继承自 `Card` 基类并使用 `@Revivable` 装饰器
- RPC 系统自动处理类实例的序列化和反序列化
- 服务器可以发送卡牌对象到客户端，客户端收到的是真正的类实例

## 开发注意事项

### 代码规范
- TypeScript strict 模式必须开启
- Vue 组件使用 `<script setup>` 语法
- 共享类型必须放在 `packages/shared` 中
- RPC 方法命名使用 camelCase，保持一致性

### 测试策略
- 单元测试：RPC 协议、房间管理、玩家管理
- 集成测试：完整的游戏流程
- E2E 测试：实际玩家交互场景

### 部署考虑
- 服务器使用 Bun runtime，部署简单
- 客户端使用 Vite 构建，支持现代浏览器
- SQLite 数据库无需额外服务，适合小型部署
